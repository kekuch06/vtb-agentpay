# Ревизия кода VTB AgentPay MVP (ноябрь 2026)

Независимая проверка кода платёжного контура и инфраструктуры. Каждый дефект сначала воспроизведён на исходной версии (коммит `1f174c7`) командой или тестом, затем исправлен отдельным коммитом. Для каждого исправления есть тест, который падает до него и проходит после.

Приоритеты: **A** — платёж и ИБ, **B** — корректность, **C** — устойчивость и инфраструктура, **D** — документация.

## Что осталось

- **Аутентификация.** Клиент — анонимная сессия в cookie. В продукте нужен вход через ВТБ Онлайн, а повышение лимитов — с подтверждением (сейчас лимит меняется без кода).
- **Ограничение частоты запросов.** Его нет. Поток `POST /api/tasks` нагружает модель, поток изменяющих запросов создаёт новые сессии.
- **Обрезка хвоста журнала.** HMAC не даёт править и пересчитывать записи, но удаление записей с конца цепочки по одной базе не обнаруживается. Нужна регулярная выгрузка головы цепочки во внешнее хранилище (SIEM, WORM).
- **Роли PostgreSQL.** В compose приложение работает под владельцем таблиц и технически может снять триггер журнала. В контуре банка нужны отдельные роли: приложению — только `INSERT` и `SELECT` в `audit`.
- **Каталоги sandbox.** Сценарии «рост цены» и «товар закончился» меняют общий тестовый каталог в памяти процесса. На общем стенде они влияют на всех клиентов, при нескольких процессах uvicorn — только на свой процесс.
- **CI** ещё не запускался: workflow добавлен, но не опубликован. Действия GitHub закреплены по тегам версий, не по SHA.
- **Документы `submission/` и файл аудита команды** в репозиторий не входят и в ревизии не проверялись.
