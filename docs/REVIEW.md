# Ревизия кода VTB AgentPay MVP (ноябрь 2026)

Независимая проверка кода платёжного контура и инфраструктуры. Каждый дефект сначала воспроизведён командой или тестом, затем исправлен отдельным коммитом. Для каждого исправления есть тест, который падает до него и проходит после.

Два этапа: **ревизия 1** — код на коммите `1f174c7` (разделы A–C ниже); **ревизия 2** — тестирование «до талого», аудит по десяти линзам и доработки после нового интерфейса ([раздел ниже](#ревизия-2-тестирование-аудит-доработки), полный отчёт аудита — [reviews/audit-plan-full.md](../reviews/audit-plan-full.md)).

Приоритеты: **A** — платёж и ИБ, **B** — корректность, **C** — устойчивость и инфраструктура, **D** — документация.

## Что осталось

- **Аутентификация.** Клиент — анонимная сессия в cookie. В продукте нужен вход через ВТБ Онлайн.
- **Обрезка хвоста журнала.** HMAC не даёт править и пересчитывать записи, роль приложения не может их удалить, но владелец базы может удалить записи с конца цепочки. Нужна регулярная выгрузка головы цепочки во внешнее хранилище (SIEM, WORM).
- **Ограничение частоты при нескольких процессах.** Окно в памяти процесса: при N процессах лимит до N раз выше. Нужен общий счётчик и доверенный прокси в `--forwarded-allow-ips`.
- **Восстановление после перезагрузки страницы.** Открытый заказ живёт на сервере, но интерфейс после перезагрузки его не показывает.
- **Прогоны моделей** DeepSeek, Qwen3 и российской модели — см. выше.
- **Документы `submission/` и файл аудита команды** в репозиторий не входят и не проверялись.
