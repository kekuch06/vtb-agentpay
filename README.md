# VTB AgentPay — MVP

Банковский слой агентной коммерции. Клиент описывает покупку обычным языком, ИИ-агент собирает и сравнивает предложения продавцов, детерминированный код проверяет условия и платёжные правила, а платёж проходит только после явного подтверждения человеком.

**ИИ готовит покупку, но не распоряжается деньгами.**

> Конкурсный проект команды SYNQ (Академия Финтеха 2026, кейс ВТБ). Не является продуктом Банка ВТБ (ПАО). Все платежи — sandbox, реальных списаний нет; каталоги продавцов тестовые.

## Сквозной сценарий

1. **Поручение:** «Найди SSD Samsung 2 ТБ с гарантией и доставкой до пятницы».
2. **Агент:** извлекает ограничения, опрашивает три тестовых каталога (у каждого своя схема данных), нормализует предложения.
3. **Проверка кодом:** бренд, категория, модель, объём, бюджет с учётом доставки, срок, гарантия, наличие, целостность карточки (prompt injection, чужие реквизиты).
4. **Заказ:** сумма берётся из повторно запрошенной карточки продавца, реквизиты получателя — из реестра банка.
5. **Policy Engine:** 10 правил до подтверждения и повторно после него, прямо перед списанием.
6. **Подтверждение:** одноразовый код, привязанный к хешу заказа; не больше 3 попыток.
7. **Платёж в sandbox и журнал:** журнал ведётся только на добавление, записи связаны хеш-цепочкой.

## Зоны доверия

```
 Пользователь ──► Web UI (React)
                     │
   ┌─────────────────┼──────────────── НЕДОВЕРЕННАЯ ЗОНА ───────────┐
   │  Разбор поручения: LLM on-prem (Ollama) │ правила (запасной)    │
   │  Адаптеры каталогов продавцов (цены и описания — любые)         │
   └─────────────────┬───────────────────────────────────────────────┘
          только Constraints / Offer после проверки схемы (Pydantic)
   ┌─────────────────▼──────────────── ДОВЕРЕННАЯ ЗОНА ─────────────┐
   │  Verifier → Сервис заказов → Policy Engine → Подтверждение     │
   │  → Платёжный sandbox → Журнал (append-only, хеш-цепочка)       │
   └─────────────────────────────────────────────────────────────────┘
```

Модель видит только текст поручения. Она не читает карточки товаров, у неё нет инструментов заказа и оплаты, а объяснение для пользователя собирается шаблоном из проверенных полей.

## Запуск

Нужны Python 3.12 (через [uv](https://docs.astral.sh/uv/)) и Node.js 18+.

```bash
make install   # зависимости backend и frontend
make run       # сборка фронтенда и сервер на http://localhost:8000
```

Режим разработки: `make backend` (API на :8000) и `make frontend` (Vite на :5173 с прокси на API).

### Локальная LLM (необязательно)

Без модели поручения разбираются детерминированными правилами. Чтобы включить on-prem модель:

```bash
ollama pull qwen2.5:3b
```

Сервер подхватит модель автоматически. Переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AGENTPAY_LLM` | `auto` | `auto` — модель, если доступна; `rules` — только правила |
| `AGENTPAY_LLM_MODEL` | `qwen2.5:3b` | любая модель Ollama (например, T-lite) |
| `AGENTPAY_OLLAMA_URL` | `http://localhost:11434` | адрес Ollama в контуре |
| `AGENTPAY_TODAY` | системная дата | фиксированная дата для воспроизводимых демо |

## Тесты и метрики

```bash
make test   # тесты: разбор поручений и атаки на платёжный контур
make eval   # прогон метрик → backend/eval/report_<parser>.md
```

Последний прогон: 40 заданий в трёх наборах, 8 атак ([подробнее](backend/eval/SUMMARY.md)).

| Способ разбора | Рабочий (20) TSR / CC | Отложенный 2 (10) TSR / CC · поля верно | Payment Safety |
|---|---|---|---|
| Правила | 100% / 100% | 100% / 100% · 6/10 | 0 из 8 |
| Qwen 2.5 3B без сверки | 60% / 100% | 50% / 75% · 2/10 | 0 из 8 |
| **Qwen 2.5 3B + сверка кодом** | **100% / 100%** | **100% / 100% · 8/10** | **0 из 8** |

Модель понимает свободные формулировки. Код принимает поле из её ответа, только если оно опирается на текст поручения, а даты и единицы считает сам: [`grounding.py`](backend/app/agent/grounding.py).

## Сценарии атак в интерфейсе

Вкладка **Sandbox**: рост цены у продавца, товар закончился, подмена реквизитов в заказе, изменение лимита на операцию. Карточка с prompt injection уже лежит в каталоге «Комплект-Про» («СУПЕРЦЕНА»).

## Структура

```
backend/
  app/
    agent/        rules.py · llm.py · orchestrator.py   — недоверенная зона
    trust/        verifier.py · payments.py             — доверенная зона
    catalogs/     3 тестовых каталога + реестр продавцов
    audit.py      журнал с хеш-цепочкой
    main.py       FastAPI
  tests/          тесты безопасности и разбора
  eval/           набор заданий и прогон метрик
frontend/src/     React + TypeScript
```

## Что не входит в MVP

Реальные карты и списания, покупки на произвольных сайтах, доступ агента к банковскому счёту, интеграция с ВТБ без согласования.
